# Cook It For Me

Steam Workshop: https://steamcommunity.com/sharedfiles/filedetails/?id=3801601464

## Текущее обновление надёжности

Обязательная проверка из корня `pz-mods`: `powershell -NoProfile -ExecutionPolicy Bypass -File tools/check.ps1 -Mod cook-it-for-me`.
Она выполняется до dev-синхронизации и сборки релиза. Публикация использует отдельную временную копию, не пересоздавая папку работающей игры.
Актуальные контракты сессии, отказов, подбора с пола, заморозки и UI описаны в `ARCHITECTURE.md`; новые игровые сценарии — в `tests/REGRESSION.md`.
После этой серии правок нужен один перезапуск игры: изменены контракты состояния, регистрация обработчиков и переводы. Watcher запускать заново через `tools/watch.cmd cook-it-for-me` после входа в мир.

## Назначение

`Cook It For Me` — QoL-мод для **Project Zomboid Build 42**, рассчитанный только на одиночную игру. По правому клику в мире игрок открывает план готовки, выбирает блюдо и стратегию подбора еды; мод сам переносит предметы, заполняет посуду водой, собирает блюдо по ванильному evolved-рецепту, ставит его на плиту, следит за готовностью и забирает результат.

Мод не добавляет предметы или рецепты: он автоматизирует существующие ванильные механики и использует ванильные `TimedAction` / `RecipeManager` API.

## Быстрый сценарий

1. `CookItForMe_Client.lua` добавляет пункт контекстного меню.
2. `CookItForMe_PlanUI.lua` строит вкладки блюд и показывает план до запуска.
3. `Cook.plan()` сканирует окружение, выбирает посуду и продукты, проверяет evolved-рецепт и рассчитывает прогноз калорий/сытости по формулам B42 без вызова `addItem()` и изменения персонажа.
4. `Cook.start()` ставит цепочку ванильных timed actions: взять посуду → вода (если нужна) → ингредиенты/специи → по настройке плита и нагрев либо завершение после подготовки.
5. `OnTick` отменяет процесс при зомби ближе 10 клеток, выключает плиту, когда блюдо готово, и переносит его в инвентарь.

## Поддерживаемые блюда

| Блюдо | Посуда | Вода |
| --- | --- | --- |
| Soup | `Base.Pot`, `Base.PotForged` | да |
| Stew | `Base.Pot`, `Base.PotForged` | да |
| Stir fry | `Base.Pan`, `Base.PanForged`, `Base.GridlePan` | нет |
| Roasted Vegetables | `Base.RoastingPan` | нет |
| Salad | `Base.Bowl`, `Base.ClayBowl` | нет |
| Fruit Salad | `Base.Bowl`, `Base.ClayBowl` | нет |

Для нагрева горячих блюд нужна рабочая немикроволновая плита; для супа и рагу также требуется раковина с водой. Салатам нужна сухая миска, плита и вода им не нужны. Пункт по правому клику по решению пользователя по-прежнему показывается только возле плиты; горячая клавиша открывает план и вдали от неё. Сканирование идёт в радиусе настройки игрока; `0` — ближайший инвентарь/зона 3×3.

## Логика выбора еды

- Пропускаются не-еда, испорченное, сгоревшее и составные готовые блюда. Приготовленные ингредиенты допускаются только для салатов и только когда их требует ванильный рецепт.
- Еда берётся из инвентаря игрока, контейнеров в радиусе и с пола; контейнеры на полу тоже учитываются.
- Стратегии: `max` — максимум калорий, `min` — минимум калорий, `hunger` — максимальная сытость.
- Не более двух ингредиентов одного `fullType`; лимит ингредиентов задаёт ванильный рецепт.
- Замороженные продукты увеличивают `minutesToCook` по доле в блюде: `base * (1 + frozenPenalty * frozenCount / addedCount)`. По умолчанию максимум +50%, половина замороженных — +25%; специи не учитываются. Ванильный нагрев и разморозка сохраняются.
- В салатах замороженные продукты разрешены без нагрева и могут мгновенно стать незамороженным блюдом. Пользовательской настройки заморозки сейчас нет; место для будущего выбора — `Dishes.allowsFrozen()`.
- До четырёх специй: сначала до двух базовых (<10 ккал, по одному типу), затем подходящие выбранной стратегии.

## Состояние и события

- Настройки игрока: `player:getModData().CookItForMe`; `finishCooking` по умолчанию включён и сохраняется между открытиями окна.
- Значения по умолчанию: `strategy=max`, `radius=4`, `frozenPenalty=0.5`; также хранятся позиция и размер окна.
- Sandbox: `CookItForMe.Debug` включает подробный вывод в `console.txt`; `debugFast` существует как скрытая отладочная настройка в ModData.
- События: `OnGameBoot`, `OnFillWorldObjectContextMenu`, `OnKeyPressed`, `OnTick`.
- Клавиша открытия плана хранится как `PZAPI.ModOptions` keybind `CookItForMe.OpenPlan`; не переносить её в ModData или Core key bindings.
- `Cook.getSession()` возвращает текущую SP-сессию. Runtime-состояние принадлежит ей; тик использует её игрока. Мод по-прежнему поддерживает только один активный процесс. Не объявлять его мультиплеерным без сетевой синхронизации и проверки серверного исполнения.

## Разработка

Все офлайн-тесты (из каталога `tests`):

```powershell
lua run.lua
```

Сборка папки для uploader'а Steam:

```powershell
powershell -ExecutionPolicy Bypass -File tools\build_workshop.ps1 -Mod cook-it-for-me
```

Скрипт создаёт `%USERPROFILE%\Zomboid\Workshop\CookItForMe\`, сохраняет существующий Steam `id=` и удаляет выходную папку перед пересборкой.

Сборка и публикация текущих файлов в существующий Steam Workshop item `3801601464`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\publish_workshop.ps1 -Mod cook-it-for-me
```

Steam должен быть запущен с аккаунтом владельца мода. SteamUploader находится автоматически через PATH или `%USERPROFILE%\.codex\tools\SteamUploader\SteamUploader.exe`; другой путь можно задать через `-UploaderPath` или `STEAM_UPLOADER_PATH`. Параметр `-PatchNote 'текст'` добавляет описание обновления, `-DryRun` выполняет сборку и проверку без загрузки. Пути в `mod-manifest.json` должны совпадать с каталогом сборки.

## Правила изменений

- Переносы и вода используют `ISTimedActionQueue`. Существующее прямое добавление через `recipe:addItem()` и восстановление контейнера изолированы в Actions; сохранять эти проверенные обходы до отдельной игровой проверки альтернатив.
- План и запуск должны использовать один и тот же объект `plan`: UI обещает игроку именно те ингредиенты, которые затем будут использованы.
- Новое блюдо описывается в `CookItForMe_Dishes.lua`: определение, порядок, посуда, правило имени рецепта, ключ UI. Добавить локализации и проверить значение `recipe:getUntranslatedName()` в игре: у салатов оно равно идентификатору `Salad`/`FruitSalad`, а не полю скрипта `Name = Make Salad`/`Make Fruit Salad`.
- Изменения сканирования проверять в игре: часть API (`IsoStove`, вода, `RecipeManager`, inventory transfer) недоступна офлайн-тесту.
- Файлы Lua и переводов хранить в UTF-8. Русский текст в текущем выводе Windows PowerShell может отображаться неверно из-за кодовой страницы, поэтому не делать перекодирование вслепую.

## Тестирование новых механик

Каждая новая механика и изменение существующей механики проходят тестирование до запуска игры.

1. До реализации описать проверяемые сценарии: входное состояние, настройки, ожидаемые действия и итоговое состояние. Включать обычный путь, границы, отсутствие нужных ресурсов, отмену, ошибку API и найденные ранее баги.
2. Расчёты, выбор предметов, построение плана и условия отмены выносить в чистые Lua-функции без PZ API. Для них добавлять offline-тесты в `tests/` с mock-предметами.
3. Игровой слой должен быть тонким: получать готовый план и вызывать PZ API. Для сложных цепочек проверять с mock API порядок `TimedAction`, переносы предметов и очистку состояния.
4. Перед завершением работы запускать все offline-тесты. Если раннер отсутствует или тест не запускается, сообщить об этом как о незакрытой проверке; не выдавать её за выполненную.
5. Для кода, зависящего от PZ API (`IsoStove`, вода, `RecipeManager`, очередь действий, UI), добавлять короткий внутриигровой регрессионный сценарий с проверяемым ожидаемым результатом и debug-логом. Не делать вид, что это покрыто unit-тестом.
6. Каждый исправленный баг сначала закреплять воспроизводящим тестом, затем исправлять код.

Автоматизация GUI-клиента не считается надёжным E2E-тестом. Она допустима только как дополнительная проверка; источником истины остаются сценарии, offline-тесты и внутриигровая проверка состояния.

# Архитектура Cook It For Me

Мод остаётся SP. Модули группируются по ответственности; собственный framework и сетевой слой не нужны.

## Зависимости

```text
Client / PlanUI → Cook (публичные точки входа)
                   ├─ Planner → Scanner, Dishes, FoodLogic, Forecast
                   └─ Session + Executor → Actions → игровой API

Scanner / PlanUI → Dishes
Shared → настройки ModData и диагностика
```

| Модуль CookItForMe_* | Ответственность |
| --- | --- |
| Dishes | Порядок блюд, посуда, вода, соответствие имени рецепта, ключ названия в UI |
| FoodLogic | Выбор ингредиентов и расчёт штрафа; без глобального игрового API |
| Scanner | Чтение окружения, контейнеров и фильтрация предметов |
| Planner | Построение плана, проверка ресурсов и совместимости с рецептом |
| Forecast | Чтение параметров рецепта, расчёт калорий и сытости без изменения игровых объектов |
| Session | Состояние одного запуска, отложенные продолжения, последовательность и завершение; без PZ API |
| Actions | Игровые действия: ходьба, перенос, вода, добавление, включение плиты |
| Executor | Порядок действий, контроль угрозы и готовности, отмена, сообщение о результате |
| Cook | Связывает модули, хранит текущую SP-сессию, регистрирует один обработчик тика |
| Client / PlanUI | Вход из контекстного меню или клавиши, захват и отображение бинда, построение окна плана |

Файлы исполнения пока остаются в shared для сохранения существующей схемы загрузки. Это не означает, что их можно запускать на сервере: сетевой протокол и серверное исполнение не реализованы.

## Контракты

- `Cook.plan(player, dishKey)` возвращает прежний plan либо `nil, failKey`.
- `Cook.start(player, dishKey, plan)` проверяет и исполняет переданный план; устаревший план отклоняется до расходования ресурсов. Активную сессию повторный старт не отменяет; для этого есть `Cook.cancel()`.
- `plan` содержит живые ссылки на игровые предметы и рецепт, а не сетевое сообщение. Настройки сохраняют прежнюю семантику ссылки на ModData; `finishCooking=false` пропускает проверки плиты и завершает сессию после успешного добавления ингредиентов.
- `Cook.getSession()` возвращает текущую сессию или nil. Runtime-поля `active`, `pot`, `stove`, `addedCount` находятся в сессии, не непосредственно в Cook.
- Session создаётся заново для каждого запуска. Она владеет игроком, счётчиками и задержкой. `finish()` делает callbacks недействительными и очищает задержку.
- Все callbacks игровых действий проходят через `session:guard()`. Новый запуск отменяет очередь предыдущего активного запуска; его callbacks не продолжают цепочку.
- Executor отвечает за игровые последствия отмены (плита и очередь). В режиме подготовки исполнитель не читает и не изменяет состояние плиты. Session сама не обращается к миру.
- Все действия мода добавляются через Actions.enqueue. Они исключаются из ванильного сброса скорости после завершения действий. Перед реальной ходьбой скорость выше 2 снижается до 2: vanilla отвергает такой путь при быстром ускорении. Пауза и нагрев не ускоряются автоматически.
- Dishes — единственный источник списка посуды и привязки названий. Для нового блюда добавить определение, позицию в порядке и переводы; проверить реальный рецепт в игре.

## Что сохранено намеренно

Сохранены прямой `recipe:addItem()`, восстановление принадлежности блюда инвентарю, звук и пауза 500 мс. Расходующее действие никогда не повторяется после неизвестного результата. Вода и подбор с пола продолжаются после vanilla perform с проверкой фактического результата; искусственные walk-actions не используются.

Forecast считает формулами по снимку метаданных, без addItem и создания предметов. Planner не меняет общий рецепт. При исполнении разрешение заморозки временно действует только внутри проверки/добавления и восстанавливается даже при исключении.

## Контроль исполнения

- Session хранит стадию, ожидаемые действия и причину завершения. Callback одноразовый и недействителен после завершения.
- Actions проверяет результат переноса и набора воды; следит за исчезнувшими/отменёнными действиями. Нет прогресса текущего действия две минуты активного реального времени — ошибка, а не бесконечное ожидание.
- Executor завершает успех, ошибку и отмену через общий путь. При ошибке выключается включённая модом плита. Заранее включённая плита при отмене остаётся включённой; при успешной готовке выключается согласно исходному поведению.
- Отслеживается точный предмет сессии. Чужое блюдо или одинаковый тип не считаются нашим результатом. Автоматическая подмена предмета при приготовлении сторонним модом не угадывается: исчезновение нашего предмета завершает процесс с причиной.
- Готовность определяется `isCooked`/`isBurnt`, а не типом результата evolved-рецепта. Контролируются питание, температура и прогресс готовки. Штраф заморозки применяется один раз с сохранением интервала до сгорания.
- Радиус 0 соответствует ближайшему 3×3. Сканирование предпочитает рабочее доступное оборудование, обходит вложенные контейнеры без дублей. Реальная ходьба перепроверяет маршрут, который мог измениться после плана.
- Выбор продуктов оценивает вклад порции по формуле прогноза. Базовых специй не больше двух. Это жадная оптимизация порций, а не полный перебор комбинаций уникальных рецептов.

Последние 40 диагностических переходов/ошибок доступны в `CookItForMe.history` и console.txt независимо от Debug. UI имеет одну открытую копию, прокрутку и закреплённые снизу кнопки готовки и закрытия. Кнопка отмены удалена. Проверки интерфейса на моках не заменяют визуальную проверку игры.

Штраф заморозки зависит от доли успешно добавленных замороженных ингредиентов: `base * (1 + frozenPenalty * frozenCount / addedCount)`. При стандартном `frozenPenalty=0.5` половина замороженных даёт +25%, полностью замороженный состав — +50% независимо от числа ингредиентов. Специи не учитываются; ванильные нагрев и разморозка сохраняются.

## Как продолжать разработку

1. Описать сценарий и добавить тест воспроизведения/ожидаемого поведения.
2. Менять модуль, которому принадлежит ответственность. Правила выбора — FoodLogic; игровая совместимость — Planner/Forecast/Actions; жизненный цикл — Session/Executor.
3. Запустить `powershell -NoProfile -ExecutionPolicy Bypass -File tools/check.ps1`: Lua 5.1, локализации, Lua-тесты и Forge Live. Тесты API используют моки и не заменяют игру.

После установки этого рефакторинга нужен полный перезапуск игры: появились новые модули, а старый обработчик OnTick мог остаться в уже запущенной Lua-сессии.

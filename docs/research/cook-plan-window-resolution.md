# Размер окна плана готовки и разрешение

Исследование выполнено 2026-09-23 для Project Zomboid Build 42.20.4, установленного локально. В `docs/research/` уже хранятся исследовательские заметки, поэтому использована эта папка.

## Вывод

Нельзя заключить, что проблема бывает только на 4K. Размер окна мода задаётся числом UI-координат, а экранный размер берётся через `Core.getScreenWidth()` и `Core.getScreenHeight()`. Ванильный Lua использует эти экранные значения как границы и центр для UI-окон. В локальных настройках игры выбрано 3840×2160, но документация API указывает тип возвращаемого значения `int` и не описывает преобразование между пикселями монитора, оконным режимом, DPI и UI-координатами. Значит, пропорции ниже точны для указанных разрешений, когда UI-координатная область равна этому разрешению; на конкретной конфигурации это следует подтвердить значениями `getCore():getScreenWidth/Height()` в работающей игре.

Build 42 специально получил улучшения интерфейса для высоких разрешений. Это относится к UI игры в целом и само по себе не доказывает автоматическое масштабирование геометрии данного окна мода. В текущем UI мод передаёт сохранённые `panelW`/`panelH` в окно напрямую, ограничивая размер шириной и высотой экрана.

## Доля экрана

Расчёт: ширина окна / ширина экрана и высота окна / высота экрана. Проценты округлены до 0,1%.

| Размер окна | Full HD 1920×1080 | 4K 3840×2160 |
| --- | --- | --- |
| 1040×640 | 54,2% × 59,3% | 27,1% × 29,6% |
| 1600×1000 | 83,3% × 92,6% | 41,7% × 46,3% |

Следовательно, 1600×1000 на Full HD действительно займёт почти всю высоту; на 4K он займёт менее половины каждой стороны. 1040×640 занимает умеренную часть Full HD, но на 4K будет выглядеть существенно меньше относительно экрана. Это геометрия окна, не оценка физического размера текста: шрифт игры настраивается отдельно.

## Локальные источники

- Установленная версия игры: `C:\Users\User\Zomboid\console.txt` сообщает `version=42.20.4`; `C:\Users\User\Zomboid\options.ini` содержит `width=3840`, `height=2160`, `fontSize=5`, `inventoryFont=Large`, `contextMenuFont=Large`. Это фактическая конфигурация этой машины, не характеристика всех игроков.
- В установленном ванильном файле `D:\steam\steamapps\common\ProjectZomboid\media\lua\client\SurvivalGuide\SurvivalGuide.lua` окно центрируется относительно `getCore():getScreenWidth/Height()`; файл также выбирает адаптацию по порогам ширины 1600 и 1920.
- В `D:\steam\steamapps\common\ProjectZomboid\media\lua\client\ISUI\ISCollapsableWindow.lua` размеры UI-элементов зависят от реальной высоты шрифта, а отдельные отступы учитывают `getCore():getOptionFontSizeReal()`. Это показывает, что размер шрифта влияет на плотность содержимого независимо от размера окна.
- В репозитории `mods/cook-it-for-me/42/media/lua/shared/CookItForMe_Shared.lua` заданы начальные `panelW = 1040`, `panelH = 640` (строки 22–23). В `mods/cook-it-for-me/42/media/lua/client/CookItForMe_PlanUI.lua` геометрия читается через `getCore():getScreenWidth/Height()`, ограничивается размерами экрана и сохраняется после изменения пользователем (строки 247–254, 664–674).
- API установленной версии — в локальном `projectzomboid.jar`; сигнатуры также опубликованы в [PZ API Documentation 42.20.4](https://pz-wiki-modding.github.io/PZ-API-Docs/) и [Javadocs Project Zomboid для `Core`](https://projectzomboid.com/modding/zombie/core/Core.html). У `Core` есть `getScreenWidth()` и `getScreenHeight()`, оба возвращают `int`. Документация не уточняет их отношение к Windows DPI scaling или координатам дисплея.

## Первичные источники о высоком разрешении

- В [официальном сообщении The Indie Stone о 4K](https://projectzomboid.com/blog/news/2023/09/sky-high/) разработчики прямо описали прежнюю проблему: на 4K интерфейс был слишком мелким; в Build 42 они планировали увеличить/переработать UI для таких экранов.
- В [официальном обзоре функций Build 42](https://projectzomboid.com/blog/features-overview-build-42-20/) заявлены улучшения, позволяющие интерфейсу лучше масштабироваться на мониторах с высоким разрешением. Это подтверждает общее направление игры, но не контракт для окна конкретного мода.
- [Официальные JavaDocs `Core`](https://projectzomboid.com/modding/zombie/core/Core.html) перечисляют типы и сигнатуры методов. Их краткая документация не определяет, в каких единицах движок сообщает размер экрана.

## Практическое следствие

Не стоит увеличивать базовый размер до 1600×1000 без ограничения долей экрана: на Full HD такое окно почти полностью закроет игровую область. При выборе размера от разрешения разумно ограничить ширину и высоту долей доступного экрана, а сохранённый пользователем размер оставить приоритетным. Формула должна использовать размеры, возвращаемые игрой, а не только классифицировать мониторы как «4K» или «Full HD». Однако пределы процентов — продуктовый выбор, источники выше их не задают.

Для подтверждения причины жалобы нужна runtime-проверка `getCore():getScreenWidth/Height()` в игре и проверка окна на Full HD/4K либо на сопоставимых виртуальных разрешениях. В текущем исследовании игровое поведение при 1920×1080 не запускалось.
